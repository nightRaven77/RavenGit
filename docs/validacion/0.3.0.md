# RavenGit 0.3.0 — remotos y acceso de lectura

Fecha: 20 de octubre de 2026. Estado: incremento de desarrollo; aceptación del MVP pendiente.

## Modelo aprobado para este incremento

Un remoto es una entrada nombrada de Git dentro del repositorio, no una cuenta ni una restricción de proveedor. `origin` es una convención. Ejemplo conceptual: `origin` → Gitea propio; `upstream` → GitHub original; `backup` → otro destino. No se configuraron estos destinos en el repositorio de RavenGit.

Las ramas locales pueden seguir ramas de un remoto; las referencias remotas son información almacenada localmente. Fetch actualiza esa información; publicar requerirá una operación push separada en una fase posterior. Las APIs de GitHub, GitLab, Gitea y Bitbucket se añadirán como adaptadores independientes para cuentas y metadatos.

## Alcance entregado

Listado local, URLs efectivas de descarga/publicación, etiqueta de proveedor cuando el hostname público es inequívoco, recuento de referencias y ramas locales con seguimiento. Un servidor propio aparece como «Servidor Git» sin asumir que sea Gitea. Alta/edición de una URL por dirección; publicación vacía hereda descarga. El nombre no se renombra en esta fase.

La edición y la conexión requieren confianza explícita por apertura. La UI comparte esa confianza con Cambios, conserva el borrador de commit al navegar y bloquea operaciones concurrentes de RavenGit. El backend vuelve a validar una huella de configuración y referencias antes de modificar/contactar.

Comprobar acceso ejecuta `ls-remote --heads`: comprueba lectura, no publicación. Fetch se limita a ramas del remoto seleccionado, con actualización atómica de refs por Git, sin tags, prune, recursión de submódulos, FETCH_HEAD, merge o push. No conecta al abrir la vista ni añade origen por defecto. Confirmación muestra el destino y los efectos. Sólo un fetch confirmado registra fecha temporal en esta apertura.

Eliminar usa `git remote remove`: elimina configuración y seguimiento remoto, conserva ramas locales, archivos y servidor. La vista anuncia estos efectos antes de confirmar.

## Credenciales y restricciones

HTTPS, SSH y rutas absolutas locales; rechaza URLs con credenciales embebidas, parámetros y transportes no admitidos. Oculta credenciales de URLs preexistentes restringidas al devolverlas a la UI. Se utiliza Git y sus helpers existentes, sin almacén de secretos propio. SSH usa modo batch, hosts ya conocidos y agente/configuración existentes. Sin prompts de contraseña, debilitamiento TLS ni aceptación automática de host SSH.

Una configuración con varias URLs, mirror o refspecs especiales se conserva en lectura. Configuración heredada se conserva sin edición local; si es estándar puede permitir lectura/fetch. Si el listado no puede interpretarse o supera límites se informa del error, sin prometer compatibilidad universal.

Configuración en varios comandos no es una transacción única. Un fallo puede producir cambios parciales; se muestra error y se relee el estado, sin reintentar automáticamente. La serialización y las huellas protegen operaciones de esta aplicación; persiste una ventana frente a modificaciones externas concurrentes. Los repositorios autorizados pueden invocar helpers configurados. Tiempo máximo de conexión 60 s; salida acotada a 2 MiB, sin volcar stderr potencialmente sensible.

## Evidencia automatizada

- Rust: 31 pruebas, incluidas 13 nuevas de remotos. Repositorios temporales y servidor bare local; no servidores de usuario ni conexiones a proveedores reales.
- Frontend: 15 pruebas, incluidas 7 nuevas de remotos con IPC simulado. Lectura sin conexión automática, confianza, selección/confirmación de fetch, consulta independiente, fallo sin fecha de éxito, edición tras revisión y configuración restringida.
- TypeScript/Vite y Clippy sin advertencias.

El escenario de fetch local compara HEAD, índice y archivos, verifica que sólo se actualice el remoto elegido y que no se cree FETCH_HEAD. Otros escenarios cubren eliminación sin pérdida de ramas/archivos, URLs de publicación separadas, borrado de pushurl, locks, estado obsoleto y preservación de configuraciones avanzadas/heredadas.

La revisión visual de la vista y la confirmación de fetch se realizó en navegador con datos sintéticos y operaciones deshabilitadas (`dev/remotes.html`); no equivale a interacción nativa ni prueba de conexión real.

## Pendiente y límites de aceptación

Compilación nativa de desarrollo macOS arm64: generada correctamente mediante `npm run tauri build -- --debug --bundles app` (RavenGit.app). No se ha verificado interacción nativa completa, autenticación HTTPS/SSH real, permisos de proveedores, Windows o Linux, accesibilidad integral, rendimiento con 100 000 commits ni firma/notarización.

Siguiente incremento propuesto: push con destino y rama explícitos, validación de divergencia y rechazo de non-fast-forward; después integración controlada con merge/rebase y recuperación de conflictos. Pull, force push, pruning, renombrar remotos y administración de upstream quedan pendientes de diseño/implementación, sin tratarlos como decisiones cerradas.
