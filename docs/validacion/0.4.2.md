## Cambios complementarios de accesibilidad e interfaz

La navegación anuncia la vista actual con aria-current. El enlace «Saltar al contenido» apunta al panel activo, que admite foco. Las ayudas se pueden cerrar con Escape sin perder el foco y admiten colocar el puntero sobre ellas. Los avisos ocupan una fila de la cabecera y no dependen de la vista activa; Cambios permite desplazamiento vertical cuando la autorización y el compositor no caben en la altura disponible.

La autorización se comparte durante esta apertura del repositorio. El texto explica que la inspección puede ejecutar filtros y que Git puede utilizar hooks, firma y ayudantes configurados. El borrador de commit se conserva al navegar y ante errores, como en la versión anterior.

## Ejecución compartida y límites

process.rs prepara un comando Git sin shell explícita, limpia variables que desvían el repositorio y desactiva lazy fetch. Cada dominio conserva sus restricciones: lecturas con locks opcionales desactivados, escrituras con índice temporal e identidad controlada, y conexiones con los protocolos/TLS/SSH no interactivos existentes.

La salida estándar se drena y conserva hasta 2 MiB más un byte para detectar exceso. stderr se drena sin guardarlo ni exponerlo a la interfaz. Una escritura que termina con resultado incierto exige comprobar HEAD/índice antes de repetir; no hay retries automáticos. No se desactivan los filtros necesarios para staging después de autorizar.

El proceso auxiliar no es una sandbox de scripts autorizados. En Unix se termina el grupo de procesos normal; un script que se independice de ese grupo requiere medidas adicionales. Windows evita un join indefinido mediante el mismo deadline, pero la terminación completa de descendientes mediante Job Objects y su validación siguen pendientes. No se declara soporte Windows validado con estas pruebas macOS.

Los clones parciales no reciben recuperación automática desde el diff. El mensaje explica que puede faltar contenido local y que debe recuperarse explícitamente desde Git. El bloqueo de publicación desde clones parciales/shallow se mantiene.

## Validación

- Rust offline: 49 aprobadas, 0 fallidas (cinco casos nuevos respecto a la revisión).
- Vitest: 34 aprobadas, 0 fallidas (cinco casos nuevos y actualización de la prueba de autorización).
- Clippy all-targets con warnings como errores: aprobado.
- TypeScript/Vite, Prettier y git diff --check: aprobados.
- CSS: igualdad exacta entre build con skills y control sin ellas; antes de la corrección, la revisión había observado 50.052 bytes con skills y 26.264 sin ellas. La versión actual incluye estilos nuevos, por lo que no se compara su tamaño contra el control antiguo como si fueran las mismas fuentes.
- Revisión visual de App completa en navegador con IPC simulado: autorización pendiente, error global desde Cambios, área de compositor desplazable y cierre de ayuda con Escape. Fixture dev/stabilization.html; no ejecuta Git ni conecta proveedores.
- Compilación nativa de desarrollo macOS arm64: aprobada mediante `npm run tauri build -- --debug --bundles app`; bundle RavenGit.app generado (32,36 MiB).

Las suites mantienen las pruebas existentes de topología, staging, commits, remotos y publicación normal. El build nativo no sustituye una interacción nativa completa. No se ejecutaron conexiones a proveedores reales, VoiceOver/Lighthouse/axe, benchmarks del grafo completo, Windows/Linux ni distribución firmada/notarizada.

## Fuera del alcance

No se implementaron creación/cambio de ramas, merge, resolución de conflictos, rebase, pull compuesto ni force push. El siguiente incremento propuesto sigue siendo gestión segura de ramas, después de revisar esta estabilización. La carpeta .agents/ y skills-lock.json del usuario se conservaron intactos y sin incorporarlos automáticamente a Git.

Referencias técnicas consultadas: [detección de fuentes Tailwind](https://tailwindcss.com/docs/detecting-classes-in-source-files) y [GIT_NO_LAZY_FETCH](https://git-scm.com/docs/git).
